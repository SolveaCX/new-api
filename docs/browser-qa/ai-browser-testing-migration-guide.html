把 AI 浏览器测试迁移到其他项目

本文把“录制核心流程、严格语义回放、再让 AI 有边界发散探索”的浏览器 QA 方案抽象成项目无关模板。目标是让任何 Web 项目都能在 CI/CD 或独立调度中运行可审计、可清理、可控预算的 AI 浏览器测试。

语言 中文 格式 单文件 HTML5 示例 仅占位符 边界 不含真实 Secret

1. 适用场景与非目标

适用场景 需要验证真实浏览器流程、邮件或第三方回调、前端异常、关键路径回归、发布前只告警门禁的项目。
迁移目标 把个人电脑录制的流程变成云端或 Runner 中可重复运行的测试，并保留证据、清理和成本边界。
不适合 纯 API 单元测试、确定性 DOM 断言已足够的流程、需要绕过 CAPTCHA 或真实支付的流程。
非目标 不自动批准发布，不访问生产写路径，不保存真实凭据，不把 AI 探索结果直接当作产品结论。
迁移原则：先让 replay 严格稳定，再增加 AI 发散。核心流程失败时，只做诊断和证据采集，不进入广泛探索。

2. 迁移决策表

决策点推荐默认值何时调整风险
运行位置 容器化执行器 + 私有 broker + 独立 cleanup 小项目可先用 self-hosted runner；强隔离项目用云 Job 或 Kubernetes Job。 直接在 CI runner 放所有凭据会扩大泄露面。
回放方式 语义 replay：按目标状态、可访问名称、URL、文本意图定位 非常稳定的控件可补充 selector，但不能只依赖坐标。 坐标回放对布局、语言、缩放和动画非常脆弱。
AI 探索 核心 checkpoint 之后开启，限制时间和 action 数 需要高置信发布门禁时，先把探索发现转成确定性测试。 无边界探索会制造费用、误报和数据访问风险。
结果处理 先只告警，报告私有存储，摘要脱敏 replay 连续稳定后，可把 replay_failed 作为阻断条件。 直接阻断发布会把基础设施波动变成交付风险。
IaC 独立 state/root，两阶段 bootstrap 已有平台模块成熟时，可复用模块但保持状态隔离。 与生产 root 混用 state 会让 drift 和 QA 资源互相牵连。

3. 目标架构

通用方案由六个边界清晰的组件组成：调度器只负责构建、部署和启动；执行器拥有浏览器与模型进程；broker 持有第三方敏感凭据；evidence 管道负责截图、日志和脱敏；cleanup 独立兜底；provider adapters 隔离云厂商差异。

边界职责禁止
调度器选择 mode、构建镜像、注入非敏感变量、等待 main/cleanup 真实结束。不持有 OAuth refresh token，不解析邮件正文，不写测试业务逻辑。
执行器启动浏览器、模型、MCP、预算控制、结果 schema 校验和 artifact 上传。不读取 broker 的 OAuth payload，不接受任意模型或任意 URL 输入。
Broker最小化暴露验证码、回调或外部系统查询能力。不返回完整邮件、header、refresh token 或任意账号查询结果。
Evidence截图遮罩、console/network 投影、路径白名单、上传前脱敏。不上传原始 Playwright output、Cookie、Authorization、完整 API key。
Cleanup用同一 run identity 重新登录并幂等删除测试工件。不依赖模型最后一句话，不把 cleanup 成功交给 AI 判断。

4. Record 格式与 Replay Contract

录制产物不是浏览器操作流水账，而是可迁移的业务意图记录。record 应描述“用户要达到什么状态”和“允许怎样恢复”，replay contract 应定义成功、失败、证据和停止条件。

推荐 Record Schema

{
  "schema_version": 1,
  "flow_id": "new-user-onboarding",
  "target_app": "APP_NAME",
  "allowed_origins": ["https://APP_STAGING_ORIGIN", "https://APP_DOCS_ORIGIN"],
  "identity_inputs": ["username", "email_alias", "password"],
  "steps": [
    {
      "id": "open-signup",
      "intent": "从公开站点进入注册页",
      "start_url": "https://APP_STAGING_ORIGIN",
      "success": [
        "URL 匹配 /signup 或注册表单可见",
        "注册按钮或标题可通过可访问名称识别"
      ],
      "selectors_hint": ["role=link[name*=注册]", "role=button[name*=Sign up]"],
      "recovery": ["刷新一次", "回到 start_url 后重新寻找 CTA"]
    }
  ],
  "checkpoint": {
    "id": "core-replay-complete",
    "must_prove": ["账号已登录", "关键资源已创建", "可清理身份已记录"]
  }
}

字段名可以按团队规范调整，但必须保留：版本、允许 origin、身份输入、步骤意图、成功断言、恢复策略和 checkpoint。

Replay Contract

契约项要求
定位优先使用 role、label、文本意图、URL 状态和业务断言；selector 仅作 hint。
恢复允许有限刷新、返回上一步、重新寻找同义按钮；禁止创建第二个测试账号来掩盖失败。
checkpoint只有核心状态可证明且 cleanup 有足够身份信息时，才能进入探索。
输出固定 JSON schema：replay、exploration、budgets、findings；额外字段 fail closed。
失败分类cleanup_failed 优先级最高，其次 infrastructure_failed、replay_failed、findings_detected、passed。
 
{
  "replay": {"status": "passed", "checkpoint_reached": true},
  "exploration": {"status": "not_started", "actions_used": 0},
  "budgets": {"replay_seconds": 600, "exploration_seconds": 300, "max_actions": 30},
  "findings": [
    {
      "severity": "low",
      "title": "标题必须描述可复现问题",
      "target_url": "https://APP_STAGING_ORIGIN/path",
      "steps": ["步骤 1", "步骤 2"],
      "expected": "期望行为",
      "actual": "实际行为",
      "evidence_paths": ["screenshots/example.png", "browser/console.jsonl"],
      "confidence": "medium"
    }
  ]
}

5. 如何把录制 Skill 去项目化

迁移时不要直接复制包含真实业务名、真实域名和个人录制痕迹的 Skill。先拆成四层：通用动作、项目配置、环境策略和敏感 broker。

  1. 抽象输入：把邮箱、用户名、密码、起始 URL、语言和 expected credit 等值改为 runtime 注入。
  2. 替换绝对事实：把“点击某产品名按钮”改成“点击进入目标工作区的主 CTA”，把真实域名改成 APP_STAGING_ORIGIN。
  3. 保留业务断言：保留“账号完成注册”“API key 可见但不复制完整 secret”“文档入口可达”等可证明结果。
  4. 移除人工接管：录制给真人的提示要改成 runtime policy，例如“本次测试已授权使用一次性身份完成注册”。
  5. 禁止模型自由扩权：Skill 只描述业务流程，不暴露 secret 名称、broker URL、云项目、bucket 或 runner 路径。
# skills/new-user-onboarding/SKILL.md
---
name: new-user-onboarding
description: Replay the staging new-user onboarding flow with runtime-provided identity.
---

Use only:
- APP_STAGING_ORIGIN
- TEST_USERNAME
- TEST_EMAIL
- TEST_PASSWORD
- get_current_verification_code
- qa_capture_screenshot

Stop at checkpoint only after:
- the account is logged in;
- the onboarding landing page is usable;
- the test-created resource can be enumerated by cleanup;
- no production origin was visited.
去项目化结果：Skill 仍保留流程语义，但把项目差异移到配置和 adapters。复制到新项目时，只需要替换配置、broker 查询逻辑和 cleanup API。

6. 执行器、Broker、Evidence、Cleanup 与 Provider Adapters

执行器

  • 启动一个 supervisor-owned 浏览器，Playwright MCP 只通过 CDP attach，不让模型启动第二个浏览器。
  • 为 Codex 或其他模型进程使用临时 home、临时 workspace、固定模型配置和固定 schema。
  • 通过 allowlist proxy 限制 origin、阻断 metadata、内网、生产域名和非 HTTP(S) scheme。
  • 将 replay 和 exploration 的预算写入 runtime state，由 MCP wrapper 在每次 tool call 前检查。

Broker

broker 是敏感系统的最小代理。它可以查邮件验证码、读取一次性回调状态或交换 OAuth code，但只能返回当前 run 需要的最小字段。

POST /v1/current-code
Content-Type: application/json

{
  "run_id": "GITHUB_RUN_ID",
  "email_tag": "qa-RUN_ID-NONCE",
  "start_time": 123456789
}

broker 必须验证 run id、alias/tag 格式、时间窗口、调用身份和请求大小。错误只返回枚举码，例如 pending、invalid_time_window、oauth_invalid_grant。

Evidence

  • 截图由受限工具触发，工具只接收逻辑名，不接收路径、selector 或关闭遮罩的参数。
  • console/network 只保存投影字段；header、body、Cookie、Authorization、query secret 在落盘前脱敏。
  • artifact 上传使用相对 POSIX 路径白名单，拒绝符号链接、路径穿越和重复 real path。

Cleanup

cleanup 必须和主执行解耦。主 job 在 finally 中清理，调度器再以 always 语义启动独立 cleanup job。人工恢复入口使用原始 run id 重算同一测试身份。

  • 列出并删除所有测试创建的 key 或资源，不能只看第一页。
  • 删除测试账号或测试工件后，重新验证登录或读取失败。
  • 若 cleanup 不能证明完成，最终状态必须是 cleanup_failed。

Provider Adapters

把云厂商差异封装在 adapters：身份令牌、对象存储、Job 执行、日志 URI、服务更新、artifact content type。核心测试逻辑只依赖接口。

interface ProviderAdapter {
  getAccessToken(audience?: string): Promise<string>;
  uploadArtifact(objectName: string, bytes: Uint8Array, contentType: string): Promise<void>;
  executeJob(jobName: string, env: Record<string, string>, args: string[]): Promise<JobResult>;
  updateRuntimeImage(resourceName: string, imageUri: string): Promise<void>;
}

8. 先严格 Replay 后 AI 发散的渐进路线

  1. 阶段 0：录制与 schema。只生成 record、result schema、redactor 测试和 cleanup 设计。
  2. 阶段 1：本地 replay。在开发机或 self-hosted runner 运行，无云部署，不上传长期 artifact。
  3. 阶段 2：云端 core。容器化执行，运行严格 replay，探索关闭；失败只告警。
  4. 阶段 3：有边界探索。checkpoint 后开启 5 分钟或 30 action，finding 只告警。
  5. 阶段 4：门禁化。将高置信 replay 失败或已转化的确定性 finding 接入 release gate。
阶段成功标准停止条件
0record 可读，schema 固定，示例结果可校验。不能证明 cleanup 路径时停止。
1核心流程在同一环境连续通过。出现 CAPTCHA、付费或生产跳转时停止。
2云端 core 和 cleanup 均可重复。broker 或 secret 生命周期不稳定时停止。
3探索 obey budget，报告可复现。发现真实高风险 bug 时先转人工 triage。
4误报率和基础设施失败率可接受。cleanup_failed 永远阻断继续推广。

10. OIDC/WIF、Secret 与 OAuth

身份设计的目标是：调度器可以部署和启动 QA，但不能读取运行时 secret；执行器可以调用 broker，但不能读取 OAuth；cleanup 可以重算身份，但不能访问 AI API key。

身份最小权限不得拥有
deployer推镜像、更新 QA service/job image、execute job、读取非敏感 output。Secret payload accessor、生产 service admin。
runtime读取模型 API key 与 identity seed、调用 broker、上传 main artifacts。OAuth secret、删除 bucket 全局权限。
broker读取 OAuth secret、写 broker 日志。模型 API key、对象存储 admin、业务数据库写权限。
cleanup读取 identity seed、读写本 run cleanup manifest。模型 API key、OAuth secret、生产 admin。

Secret 规则：OAuth refresh token、模型 API key、验证码、完整测试邮箱、完整 API key 和密码不得进入 Terraform state、GitHub output、summary、日志、截图或提交文件。

OAuth 应使用最小 scope。若 OAuth 平台存在 testing token 过期限制，首跑只能算 bootstrap；发布为生产状态、重新授权、轮换 secret 后，再跑一次完整流程，才能声明可重复。

11. 数据与隐私

  • 每次 run 使用一次性身份，使用 HMAC(seed, run_id) 派生 username、email tag 和 password。
  • 报告只保存 run-scoped 标识，不保存完整邮箱、密码、验证码、Cookie 或完整 key。
  • 浏览器允许访问 staging origin 和只读 docs origin；生产、metadata、RFC1918、localhost、非 HTTPS 默认拒绝。
  • 截图前遮罩 input、textarea、contenteditable、验证码字段、已知 secret 和完整 alias。
  • 私有报告存储设置最短可接受生命周期，例如 7 到 14 天；不要把报告复制到 issue 或聊天。
  • 模型输出必须经过 redactor 和 schema 校验；AI 叙述不能覆盖 runtime cleanup 状态。

12. 报告与仅告警模式

首版建议只告警：GitHub Summary 或发布系统只显示状态、replay、exploration、finding 数量、cleanup 状态和私有报告 URI。详情留在私有对象存储。

状态含义默认动作
passed核心回放通过、报告上传、cleanup 验证完成。绿色。
findings_detected核心通过，探索发现至少一个非 info finding。红或黄，人工 triage。
replay_failed核心流程未达 checkpoint。红，修复 replay 或产品回归。
infrastructure_failed模型、浏览器、broker、OAuth、上传、schema 或云配置失败。红，先排基础设施。
cleanup_failed无法证明测试工件已删除。最高优先级红，运行 cleanup-only 或人工处理。
 
### AI Browser QA
- status: findings_detected
- replay status: passed
- exploration status: passed
- exploration actions: 18
- finding count: 1
- cleanup status: cleanup verified
- report_uri: PRIVATE_REPORT_URI

13. 预算、并发与超时

预算建议默认值说明
Workflow timeout90 到 120 分钟包含构建、推镜像、main、cleanup 和取 manifest。
Main job hard timeout20 分钟云平台硬限制，必须大于内部 deadline。
Supervisor deadline14 分钟预留清理和上传时间。
Exploration5 分钟或 30 actions先到即停，core 模式禁用 checkpoint 后 actions。
Cleanup job5 到 20 分钟按业务删除复杂度设置，无自动重试，使用 cleanup-only 显式恢复。
并发每环境 1避免邮箱验证码、一次性身份、配额和业务状态互相干扰。
并发要从业务资源倒推。如果每次测试创建账号、key、订单、邀请或临时 workspace，默认按环境串行，直到 cleanup 和隔离策略证明可并发。

14. Terraform / IaC 两阶段 Bootstrap

推荐把 Browser QA 放在独立 IaC root 和独立 state。第一阶段只创建基础设施和 Secret 容器；人工通过安全通道写入 secret version；第二阶段再创建引用 latest secret 的 workloads。

  1. Phase A：Artifact repository、service accounts、Secret containers、WIF、report bucket、bucket IAM。
  2. Secret versions：通过云控制台、stdin 或安全 secret pipeline 写入模型 key、identity seed、OAuth JSON。
  3. Phase B：broker service、main job、cleanup job、resource-level invoker/developer IAM。
  4. Steady state：配置保持 create_workloads=true，避免日常 plan 试图销毁 workloads。

15. 迁移步骤与分阶段 Checklist

准备阶段

  • 列出目标环境、允许 origin、禁止 origin、一次性身份策略和 cleanup API。
  • 确认不会触发真实付款、真实模型调用、生产写操作、邀请奖励或不可逆副作用。
  • 定义 result schema、manifest schema、finding 字段和状态优先级。
  • 写 redaction 测试，覆盖邮箱、alias、密码、验证码、Cookie、Authorization、API key。

录制与去项目化

  • 录制核心流程，并把每一步改写为业务意图和成功断言。
  • 把项目名、域名、个人邮箱、绝对路径和真实资源名替换为占位符。
  • 将验证码、OAuth、第三方回调接入 broker，而不是暴露给模型。
  • 在本地或隔离 runner 中验证 replay 可达 checkpoint。

云端执行

  • 构建非 root 镜像，固定浏览器、MCP、模型 CLI 和语言运行时版本。
  • 部署 broker、main job、cleanup job，并确认 IAM 最小化。
  • 启用私有报告 bucket，设置生命周期删除和 public access prevention。
  • 先运行 core，cleanup 成功后再运行 normal。

推广阶段

  • 连续多次 core 通过后，把 staging merge 接入只告警模式。
  • 探索 finding 先人工 triage，再转成确定性回归测试。
  • 建立 cleanup-only runbook，要求使用原始 run id。
  • 每次扩大触发范围前，复查成本、配额和误报率。

16. 验收标准、回滚与故障排查

验收标准

  • 核心 replay 每一步都有可验证断言，不依赖坐标。
  • AI 无法访问生产 origin、metadata、内网和未授权 docs context。
  • broker 拒绝匿名调用和越权身份，且只返回当前 run 的最小结果。
  • 报告私有、脱敏、路径白名单生效，manifest 最后上传。
  • main 失败、模型超时、workflow 取消后，cleanup-only 能用原始 run id 恢复。
  • Secret payload 不在 IaC state、日志、summary、截图、artifact 或提交文件中出现。

回滚策略

问题回滚保留
触发噪声过大关闭自动 workflow_call 或移除 required check。保留手动 dispatch 和云资源。
镜像版本坏回滚 QA service/job image 到前一 tag。不改 secret，不删报告。
broker OAuth 失效暂停 normal，轮换 OAuth secret 后跑 core。不盲目重试。
cleanup_failed运行 cleanup-only；仍失败则人工按 run id 查私有报告。保留证据直到处理完成。
需要撤销整套 QA先停触发，再按 IaC 审批销毁 QA 专属资源。不要用手工删除制造 drift。

故障排查

症状优先检查常见修复
manifest 缺失上传权限、bucket lifecycle、main job 是否到达报告阶段。修复对象存储权限；若 cleanup 未跑，先 cleanup-only。
验证码 pending 超时邮箱 alias、sender、subject、OAuth scope、时间窗口。修复 broker 查询条件，不让模型重发多封邮件。
replay 找不到按钮文案语言、role、URL 跳转、动画遮挡。更新语义 selector hint 和恢复策略。
探索超预算MCP wrapper phase state、action 计数、core/normal mode。fail closed，修预算状态机。
报告出现敏感信息redactor 覆盖、截图遮罩、console/network 投影。立即限制报告访问，修脱敏测试后重新运行。

17. 成本估算框架

先用公式估算，再用真实账单校准。不要只看模型 token；浏览器容器、对象存储、日志、NAT、OAuth/broker 请求和工程维护都要计入。

monthly_cost =
  runs_per_month * (
    build_minutes * ci_build_rate
    + main_job_minutes * container_vcpu * vcpu_rate
    + main_job_minutes * container_gib * memory_rate
    + cleanup_job_minutes * cleanup_vcpu * vcpu_rate
    + model_input_tokens * input_token_rate
    + model_output_tokens * output_token_rate
    + broker_requests * broker_request_rate
    + artifact_gib_month * storage_rate
    + log_gib * logging_rate
  )
  + fixed_private_network_cost
  + maintenance_hours * engineering_hour_rate
成本杠杆降低方法
运行次数PR 只跑轻量 contract，staging merge 跑 core，release candidate 跑 normal。
浏览器时间缩短 replay 恢复次数，失败时不进入探索。
模型费用固定 prompt、限制 tool action、使用 schema 输出、避免重复上下文。
日志和截图只保存关键截图、投影日志、生命周期删除。
并发每环境串行，避免争抢导致重试和清理成本。
